# Moving from GitLab to GitHub

This procedure moves a repository's CI declaration when the repository is
released on GitHub. It preserves the `## workflows` rows: the same rows are
rendered by `lablith` on GitLab and `actlith` on GitHub.

## Prerequisite

This page is blocked on pipelith Q3, the config-file-name open question. Do
not perform the move until that question is resolved and the corresponding
`actlith` release is available. Once it is resolved, use the config names
specified by that release; the steps below are the V67 procedure.

## One reviewed repository commit

Before editing, make sure the working tree is clean and inspect the current
render:

```sh
git status --short
lablith gen --check
lablith check
lablith report
```

Then make all of the following changes in one reviewed commit:

1. Rename `.lablith` to `.actlith`.

   ```sh
   git mv .lablith .actlith
   ```

2. In `.actlith`, remove the GitLab-only `## images` and `## runners`
   sections. Keep `## workflows` unchanged. For each `## hand-written`
   entry, convert the file's contents from GitLab CI to GitHub Actions,
   create the corresponding `.github/workflows/` file, and review the
   conversion. Keep `## hand-written`, but only then rewrite each listed
   path from the GitLab layout to its corresponding `.github/workflows/`
   path.

3. Generate the GitHub workflows:

   ```sh
   actlith gen
   ```

4. Validate the generated workflows and every converted hand-written
   workflow before deleting any GitLab files:

   ```sh
   actlith gen --check
   actlith check
   actionlint .github/workflows/*.yml .github/workflows/*.yaml
   ```

5. Delete the GitLab-generated files and directory:

   ```sh
   rm .gitlab-ci.yml
   rm -rf .gitlab/ci scripts/lablith
   ```

6. Review the complete diff. Confirm that every workflow is generated by
   `actlith` or listed under `## hand-written`, and that the GitLab files and
   scripts are gone. Commit the rename, registry edit, generated workflows,
   and deletions together.

The `## workflows` rows must not be rewritten as part of this move. If a row
is not portable to `actlith`, stop and resolve that separately before
releasing; the migration is not a kind conversion.

## After the repository commit

Perform these operations outside the repository:

- Delete the GitLab schedules for the migrated rows.
- Delete the GitLab CI/CD variable `LABLITH_TOKEN` if no remaining GitLab
  pipeline uses it.
- Run `actlith report` and create the GitHub secrets it lists, using the
  repository's normal protected-secret process.
- Inspect every converted hand-written workflow for `secrets.*` references and
  provision those secrets too, or reconcile them with the Q3 secret inventory.

Do not delete a schedule or secret still needed by another GitLab pipeline.
