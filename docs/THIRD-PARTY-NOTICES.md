# Third-party notices

`lablith` ships **4 direct dependencies**, which pulls in 15 crates in
total. This file says what they are, why each one is there rather than
hand-rolled, and what licence the set carries.

## Why each direct one is there

The project's own constraint is *keep dependencies minimal, and justify
each one in `SPEC.md`*. The three clap crates live in one node,
`src/cli` (`src/cli:R14`), and nothing else links them; pipelith lives
behind `src/core`.

- [`clap`](https://github.com/clap-rs/clap) (derive): the argv table,
  `--help` with examples and usage errors. Built without colour or
  terminal-size features: `std`, `derive`, `help`, `usage`,
  `error-context`, `suggestions`.
- [`clap_complete`](https://github.com/clap-rs/clap): `lablith
  completions <shell>`, generated from the same table.
- [`clap_mangen`](https://github.com/clap-rs/clap): `lablith man`, the
  roff man page from the same table.
- [`pipelith`](https://github.com/pr0d1r2/pipelith): the forge-neutral
  core lablith shares with actlith: the pipe-table registry, the YAML
  writer, the generated-file drift check, the kind catalogue and detect.
  Shared rather than copied, so both tools read a row and write a file
  the same way. It is std only and pulls in nothing else.

HTTP for `lablith pin` is the `curl` program, not a crate.

## Not dependencies: the tools in the gate

These appear in the dev shell and the gate, and are **not** linked into
`lablith`. A consumer building the crate never sees them.

- [`hk`](https://github.com/jdx/hk): the gate runner.
- [`pkl`](https://github.com/apple/pkl): evaluates `hk.pkl`.
- [`pklith`](https://github.com/pr0d1r2/pklith): materializes the hk
  steps from `.pklith`.
- [`microlith`](https://github.com/pr0d1r2/microlith) (`mth`): owns the
  `SPEC.md` format and checks it.
- [`sherd`](https://github.com/pr0d1r2/sherd): checks the federated spec
  and holds the coverage floor.
- [`itok`](https://github.com/pr0d1r2/itok): token counting for the
  per-file ceilings.
- [`actlith`](https://github.com/pr0d1r2/actlith): renders this
  repository's GitHub workflow.
- [`check-jsonschema`](https://github.com/python-jsonschema/check-jsonschema):
  validates the rendered pipelines against GitLab's CI schema, which is
  vendored under `tests/schema/` (MIT, GitLab B.V.).
- [`actionlint`](https://github.com/rhysd/actionlint) and
  [`zizmor`](https://github.com/zizmorcore/zizmor): lint the GitHub
  workflow.
