# The `.lablith` registry

`.lablith` at the repository root is the one file you write. lablith
reads it, and nothing else, to decide which pipeline files exist and what
goes into them; `lablith gen` renders it, and `lablith check` holds the
project to it. The same file with the same lablith version always renders
the same bytes: no clock, hostname or network goes into the output.

`lablith seed --init` writes a first one from what your project already
has. After that it is yours: lablith never rewrites it, except
`lablith pin`, which rewrites only its `## images` section.

## Shape

```text
format 1

# A comment line starts with `#`.

## workflows
id|kind|systems|cache|args
ci|gate|-|my-cache|-
pkg|build|x86_64-linux,aarch64-linux|my-cache|package=hk,timeout=60

## images
image|version|digest
nixos/nix|2.35.3|sha256:ff480dbb23511aa1c10710aa068ceea5b93fed9bfce5f5379f3a6b07282cbc7b

## runners
system|tags
aarch64-linux|nix, arm64

## hand-written
path|reason
.gitlab/ci/release.yml|publishes a release; no kind for it yet
```

- The first line is `format 1`. A file with a newer format is refused, so
  an old lablith never misreads a new file.
- Each section starts with `## <name>` and a header row, then one row per
  line, cells split on `|`.
- `-` is an empty cell. `\|` is a literal pipe inside a cell.
- Lines starting with `#` are comments, anywhere.
- A bad row stops everything (exit 2) with the line number and the fix:

  ```text
  .lablith:5: unknown kind `lint`
    fix: use one of `gate`, `build`, `update-pins`, `upstream`
  ```

## `## workflows`

The same section, with the same columns and rules, as actlith's: a row
valid here is valid in `.actlith`. Each row is written to
`.gitlab/ci/<id>.yml`, and `.gitlab-ci.yml` includes it.

| column | meaning |
| --- | --- |
| `id` | the file name and the prefix of every job: `<id>:<job>` |
| `kind` | `gate`, `build`, `update-pins` or `upstream`; see [KINDS-GITLAB.md](KINDS-GITLAB.md) |
| `systems` | nix systems, comma-separated; `-` = the kind's default |
| `cache` | a cachix cache name; `-` = no cache |
| `args` | `key=value` pairs, comma-separated, checked against the kind |

An unknown kind, arg or system is an error, never ignored. Args and
systems split on `,`, so an arg value cannot hold a comma. Every kind
takes `timeout` (job minutes, default 30).

## `## images`

Optional. lablith ships a pin for the `nixos/nix` image its jobs run, by
its multi-arch index digest. A row here replaces or adds a pin.
`lablith pin` fills this section from the registry, and
`lablith pin --dry-run` prints the rows without writing them. GitLab
only: it does not move to `.actlith`.

## `## runners`

Optional. Each nix system's jobs carry the tags `nix` and the system name
unless a row here gives that system its own tags. A self-hosted fleet
chooses its own tags; this repository ships none of anyone's. GitLab
only.

A row whose tags are `-` skips that system on this forge, for a fleet
with no runner for it: its gate and build jobs are not rendered, the
build kind's `check` still evaluates it, and `lablith report` marks it
skipped. The `## workflows` rows stay as they are, so they still match
`.actlith`. A row left with no system to run on, a bump row on a skipped
system, and a skipped `x86_64-linux` under a build row (whose `check`
and `verify-cache` run there) are refused.

```text
## runners
system|tags
aarch64-linux|-
aarch64-darwin|-
```

## `## hand-written`

CI files lablith does not generate, each with the reason. The root file
includes each one. `lablith check` fails on a CI file that is neither
generated by a row nor listed here, on a listed path that does not
exist, and on a path both listed and generated.
